# Budibase Dashboard – Installation and Configuration Guide

## 1. Overview

This directory contains the exported Budibase application configuration for the **Supermarket Management Dashboard**.

The application is developed using Budibase's low-code development platform and uses PostgreSQL as its external database.

The dashboard provides different screens and functionalities for supermarket management, including:

- Home Dashboard
- Manager
- Department
- Employee
- Update Stock
- Public Offers
- Employees Database

This guide explains how to import, configure, run, and test the Budibase application in another environment.

## 2. Technology Stack

| Technology | Purpose |
|---|---|
| Budibase | Low-code application development |
| PostgreSQL | External relational database |
| Supabase (if used as the PostgreSQL host) | Hosted database service |
| GitHub | Source control and project versioning |
| Visual Studio Code | Project file management |

## 3. Prerequisites

Before installing the application, make sure you have:

1. A Budibase account or an accessible self-hosted Budibase instance.
2. Access to the project's GitHub repository.
3. Access to a PostgreSQL database.
4. The required database credentials.
5. The original Budibase workspace export file.

**Important:** The extracted files in this directory are maintained for project version control. To import the application into another Budibase workspace, use the original export file generated by Budibase, rather than assuming that the extracted folder can be imported directly.

## 4. Clone the GitHub Repository

Clone the project repository to your local machine.

```bash
git clone <GITHUB_REPOSITORY_URL>
```

Navigate to the project directory:

```bash
cd Supermarket-handler
```

Open the project in Visual Studio Code:

```bash
code .
```

Navigate to the Budibase application directory:

```text
Supermarket-handler/
└── Budibase_sachini/
    ├── chunks/

    ├── db.txt
    ├── manifest.json
```

The exported application files provide a version-controlled reference to the Budibase application configuration.

## 5. Import the Budibase Application

### Step 1: Access Budibase

1. Visit https://budibase.com/.
2. Sign in to your Budibase account.
3. Open your Budibase workspace.

### Step 2: Import the Application

1. Open the workspace selector.
2. Select the option to import a workspace.
3. Choose the original Budibase workspace export file.
4. If the export is encrypted, provide the export password.
5. Complete the import process.
6. Open the imported application.

The imported workspace should contain the application screens and configuration included in the export.

**Note:** The import process may require additional configuration, particularly for external database connections and credentials.

## 6. Configure the PostgreSQL Database Connection

The application uses PostgreSQL as its external database.

After importing the application, configure the PostgreSQL connection.

### Step 1: Open Data Tables

1. Open the imported application in Budibase.
2. Navigate to **Data Tables**.
3. Locate the PostgreSQL datasource.
4. Open its connection settings.

### Step 2: Configure Database Credentials

Enter the connection information provided by the database administrator.

| Configuration | Required Information |
|---|---|
| Host | PostgreSQL server hostname |
| Port | PostgreSQL port (commonly 5432) |
| Database | Database name |
| Username | Database username |
| Password | Database password |
| SSL | Enable if required by the database provider |

For a Supabase-hosted PostgreSQL database, obtain the connection details from the Supabase project dashboard.

Do not use credentials from another developer's personal account. Each environment should use its own authorised database credentials.

### Step 3: Fetch Database Tables

1. Verify the database connection.
2. Select **Fetch Tables** if required.
3. Select the tables used by the application.
4. Confirm that the tables are available in Budibase.

The application uses database tables such as:

- products
- departments
- employees
- Public Offers
- add stock
- customer_offers
- Expiry
- Stock Value

The exact tables required depend on the exported application configuration.

## 7. Verify Database Relationships

After connecting PostgreSQL:

1. Open the datasource configuration.
2. Navigate to the relationships section.
3. Verify the relationships between relevant tables.
4. Recreate any missing relationships if necessary.

Check that the application can retrieve the required product, department, employee, stock, and offer information.

## 8. Configure Application Permissions

The application includes different user roles and screens.

After importing the workspace:

1. Open the application's access settings.
2. Verify the available user roles.
3. Configure the appropriate permissions.
4. Check that users can access only the screens and data intended for their roles.

Test the application using the available user-role preview options.

## 9. Preview and Publish the Application

Before making the application available to users:

1. Open the imported application.
2. Select **Preview**.
3. Navigate through all dashboard screens.
4. Verify database connectivity.
5. Test the main application functionalities.
6. Resolve any missing configuration or connection errors.

After successful testing, publish the application using Budibase's publishing controls.

## 10. Application Testing Checklist

Use the following checklist to verify the imported application.

- [ ] Application imports successfully.
- [ ] PostgreSQL connection is working.
- [ ] Required database tables are accessible.
- [ ] Home Dashboard loads correctly.
- [ ] Manager screen works correctly.
- [ ] Department screen displays department information.
- [ ] Employee screen displays employee information.
- [ ] Stock update functionality works.
- [ ] Public Offers screen displays offer information.
- [ ] Employees Database screen displays the required records.
- [ ] User permissions work correctly.
- [ ] Application can be published successfully.

## 11. Troubleshooting

| Issue | Possible Solution |
|---|---|
| PostgreSQL connection fails | Verify host, port, database name, username, password, SSL settings and network access. |
| Database tables are missing | Fetch the required tables again from the PostgreSQL datasource. |
| Application screens display errors | Check database connections, data bindings and permissions. |
| Imported application is incomplete | Verify that the original workspace export file is being used. |
| User cannot access a screen | Check application access settings and user roles. |
| Database records are not displayed | Verify table access, query configuration and database permissions. |

## 12. Security and Configuration Notes

- Never commit database passwords, API keys or private access tokens to GitHub.
- Do not share production database credentials in project documentation.
- Use environment-specific database credentials.
- Ensure that database users have only the permissions required by the application.
- Protect exported workspace files because they may contain sensitive configuration.
- Use encrypted exports when sharing application configurations containing sensitive information.
- Back up the PostgreSQL database separately.

## 14. Notes for Developers

This repository maintains the exported Budibase application files for version control and collaboration.

When making changes to the dashboard:

1. Make the required changes in the Budibase builder.
2. Test the changes using Preview.
3. Export the updated workspace.
4. Update the corresponding exported files in this repository.
5. Commit and push the changes to GitHub.
6. Document any required database schema changes separately in the database documentation.

The PostgreSQL database and Budibase application configuration should be maintained separately to support reproducibility across different development environments.
